## 二十六、物理事件链与状态连续性（sd25-physics-prompt 蒸馏）

### 核心方法（I 自述）

Seedance 2.5 的物理可信度不靠「realistic physics」这类许愿词，靠**把每个动作写成一条可见的因果链**，并让不可逆状态**跨段持续存在**。模型对「初始态→原因→响应→耦合响应→终态」的显式书写遵从度远高于形容词堆砌。

### 应用场景（A2）

- 提示词里有材质互动（水/火/尘/布料/毛发/食物）、碰撞、受力、湿滑、破碎时
- 多段视频里道具/服装/环境会留痕（湿了、破了、脏了、倒了）时
- 用户反馈「物理假」「物体自己回血」「上一段打翻的东西下一段又好了」时

### 可执行写法（E）

**物理事件链五步**（每个需要物理控制的节拍只写适用的部分）：

```
1 初始态 — 材质/形状/湿度/固定点/表面状况
2 原因    — 力源/接触点/方向/速度（先因后果，反应不得早于可见触发）
3 主响应  — 弯曲/断裂/流淌/散射/压缩/撕裂
4 耦合响应 — 衣物/头发/碎屑/液体/阴影随主响应联动
5 终态    — 每个重要物体停在哪、哪些状态变化可见
```

**术语→可见证据翻译表**（弱写法 → 强写法）：

| ❌ 弱（许愿词） | ✅ 强（可见证据） |
|---|---|
| realistic cloth physics | 水溅到棉布衫上，沿织纹扩散，纤维变暗加重，湿区下垂 |
| realistic fluid dynamics | 茶水泼出后先呈弧线，落地溅开，桌面残留水膜反射窗光 |
| cinematic physics | 裂纹从撞击点辐射展开，碎片分离后落地弹跳一次 |
| 50-source face lock | 转身过程中面部比例与五官特征保持一致 |

**状态连续性铁律**（跨段不重置）：
- 湿布保持湿，只会更沉更垂；弯了的金属保持弯，除非有可见外力
- 打翻的碎片留在地上；灰尘留在表面直到风/手/水带走
- 交接的物件离开 giver 的手后就只在 receiver 手里
- **切割处从上一段的可见终态开始**（与 01 §OUT 闭合链同源，OUT 清单里必须包含物理状态：湿/破/脏/倒）

**最小物理模型**：每个节拍一个主机制 + 至多两个因果相关的次级机制。术语堆叠 ≠ 控制力。不兼容行为禁止：干沙不水流、纯机械碰撞钢不熔、静止光源不投游移影子。

**全身移动接地耦合环**（行走/奔跑/追击/楼梯/坡地/碎石/落地/停止/转向视为一个耦合环）：
```
support/contact（支撑/接触） → center-of-mass transfer（重心转移） → push-off/flight（蹬地/腾空）
→ terrain response（地形响应） → secondary motion（次级运动） → camera-relative motion（相对镜头运动）
```
只激活画框能证明的层——特写不证明脚步时，不往提示词注入脚部 IK 类术语。（与物理事件链五步同族不同轴：五步管单物体受力因果，本环管全身移动的接地证明。）
（来源：MOKE action-choreography-reference，2026-10-06f 蒸馏）

### 边界（B）

- 简单对话/走位戏不需要物理链，加了反而挤占时长预算
- 不重复模型营销术语（原生4K全局光照等）当能力——翻译成可见行为
- 物理细节只为改变可见结果而加，不把简单场景变成特效演示

## 二十七、反套路替换与提示词污染防护（antislop + contamination-guard 蒸馏）

### 核心方法（I 自述）

两类隐形失败：①**套路词**（cinematic/epic/dynamic）——模型接不到可执行信号，产出模板化画面；②**语义污染**——上一轮的纠错痕迹、旧失败道具、冲突约束残留在提示词里互相打架。两类都要在交付前扫掉。

### 应用场景（A2）

- 提示词里出现「电影感强/画面震撼/氛围感拉满」这类空泛词时
- 同一会话改了多轮、用户否掉过几个方案后再写新提示词时
- 提示词越写越长但生成结果反而变差时

### 可执行写法（E）

**反套路可见性测试**（filler → 追问含义 → 强替换）：

| Filler 词 | 追问 | 强替换 |
|---|---|---|
| cinematic / 电影感 | 什么镜头+什么光让它电影？ | locked close-up, warm practical key, cool rim light |
| epic / 史诗感 | 尺度和赌注是什么？ | wide low-angle, tiny figure against storm wall |
| dynamic / 动感 | 什么在动、多快、停在哪？ | fast lateral track ending on the hero label |
| 氛围感 | 什么颗粒/光/声在空气里？ | dust motes in a low sun shaft, distant traffic hum |

**污染七类扫描**（改多轮后必查）：

1. 旧上下文残留——上轮的场景/道具还在本轮提示词里
2. 纠错泄漏——「不要XX」把被否掉的旧元素又写进了文本（否掉的直接删，不描述）
3. 默认模板污染——套用旧模板带进了本场景不适用的条款
4. 标签过载——抽象标签（高级感/大片感）替代了可见证据
5. 正向语义过重——同一动作用近义词写了多遍，意外获得全局权重
6. 内部术语泄漏——审核用语/工作流用语混进了生成文本
7. 语义冲突——两条控制语句要求相反效果（既要「慢推」又要「快切」）

**删除测试**：逐条问「删掉这半句，有没有任何一个唯一的可见/可听选择消失？」——没有就删。

**二元判定门**：PASS = 每条面向模型的子句都有当前来源和唯一职责；否决项已改写为当前正向事实；每个核心机制只出现一次。FAIL = 旧概念仍在活动 / 提示词本身解释了不想要的生成结果。

### 边界（B）

- 不要过度矫正：用户自带的风格词（哪怕略空泛）先问意图再替换，不擅改
- 污染扫描只在多轮修订场景强制执行，首轮新写提示词只需过反套路替换
- 与 00 审核把关的关系：00 查格式与结构红线（硬错误），本节查语义卫生（软污染），先后执行、不互替

## 三十七、生成侧失败模式库与负向词纪律（higgsfield-ai-prompt-skill 蒸馏）

> 来源：github.com/OSideMedia/higgsfield-ai-prompt-skill（MIT）· negative-constraints.md C1–C5 + vocab B-13 · 2026-10-12 蒸馏
> 定位：**生成侧**的失败模式库（模型会怎么坏）与**负向词的合法性纪律**。与 §二十七 污染防护**不同轴、并列不合并**：那边管**时间轴**上的多轮修订残留（旧轮次污染），本节管**空间轴**上的全帧作用域（整帧降质）与负向词该不该写；交付前两类**并列扫描、不互替**。

### 核心方法（I 自述）

**顶层法条：你写的词就是你召唤的词（the words you write are the words you summon）。**

法条原文：

> "Say what you want, not what you avoid — the words you write are the words you summon, **including the ones inside a 'no'.**"

（原文定位：让一部制作站得住的四件事之一——**生产级法条**，非编辑偏好。）

**论证一 · 颜色战争（The colour war）**。一部承诺冷青绿走廊的片子，走廊反复被翻成暖黄——因为参考素材本身在泄漏（一扇亮窗、一盏暖球灯），模型把它放大。此时负面清单（"no yellow"）**毫无作用**。正解不是禁止，而是**分配**它：

```
The dominant color must be cold teal-green. Yellow exists only inside
the lamp bulb and a palm-sized halo beneath it. If the frame turns
yellow, the frame is wrong.
```

注意这个形状：它不禁止黄色，而是**分配**它——一个具名来源 + 一个给定尺寸 + 一句模型可自测的失败条件（"if the frame turns yellow, the frame is wrong"）。

**论证二 · 参考非契约（A reference is not a contract）**。参考照片带一扇无法裁掉的红亮窗，正解不是禁令，而是对影片世界的一句**事实陈述**：

> "That window glowing in the reference is switched off in our film."

模型接受了它。结论：**参考不是契约**——正向说出它与本片的差异，胜过禁止参考所展示的东西。

### 应用场景（A2）

- 生成结果出现肢体/面孔/质感/时序类**可复现的坏法**，需要按图索骥改写法时
- 准备往提示词里写 "no X" / "don't X" / "avoid X" **之前**（先过 E2 禁令合法性测试）
- 用户抱怨「加了质量词反而更糊」「说了不要 X 反而来 X」时
- 多轮修订后的提示词交付前（与 §二十七 污染七类**并列执行**：那边扫时间轴残留，本节扫空间轴作用域）

### 可执行写法（E）

**E1 · 七大类失败模式（第 7 类判为不收录）**

**第 1 类 · Body / Motion Artifacts（身体与运动）—— 7 条**
起因：模型无法在单次生成里解算复杂物理动作（"can't resolve complex physical actions in a single generation"）。

| 失败模式 | 成因 | 预防写法要点 |
|---|---|---|
| Floating / extra limbs（悬浮/多余肢体） | 姿势含糊或被遮挡时模型虚构附肢 | "Anatomically correct, all limbs visible and naturally positioned" |
| Limb merging（肢体合并） | 两角色过近，模型分不清谁的手臂 | 保持一臂距离或分镜；"distinct body separation between characters" |
| Unnatural body proportions（比例失真） | 过量的、互相冲突的体型描述（高 + 紧凑）或极端角度 | 只留一个体型描述并保持一致；避免矛盾体格线索 |
| Jittery / stuttering motion（抖动/卡顿运动） | 一个 clip 里要求的动作过多，模型在其间震荡 | 每 clip 1 主 + 最多 1–2 次；复杂序列拆分生成 |
| Motion morphing on fast action（高速动作形变） | 高速运动超出模型时间一致性 | 先按 Slow Mo 生成，后期加速（CapCut/Premiere/DaVinci） |
| Specific martial arts failing（具名武术招式失败） | 具名招式需精确多帧编排 | 写 "general fighting energy" 或 "struggling"；**描述结果而非技术** |
| Grappling renders as embracing（缠斗被渲染成拥抱） | 近距离身体接触对模型有歧义 | 动作戏用**纯文本**（不用平台元素引用）；描述身体位置，不写缠斗名称 |

**第 2 类 · Face / Identity Artifacts（面孔与身份）—— 6 条**
起因：模型跨帧或跨代丢失对角色身份的追踪（"loses track of who a character is across frames or generations"）。

| 失败模式 | 成因 | 预防写法要点 |
|---|---|---|
| Face morphing / shifting（面部形变/漂移） | 无身份参考，或提示词内冲突的外观描述 | 多镜工作挂角色身份参考（identity reference）；移除矛盾的外观描述 |
| Identity drift across shots（跨镜身份漂移） | 各 prompt 间角色描述在变，或身份与运动混写同一 block | **跨所有 prompt 复制粘贴完全相同的角色描述**；Identity Block 与 Motion Block 分离 |
| Character swap（双角色互换） | 动作戏中用平台元素引用，模型混淆谁是谁 | 元素引用只用于静态/慢速场景；动作戏用纯文本；主角写在 prompt 最前 |
| Face warping during camera moves（运镜中面部扭曲） | 身份描述与时间/运动语言混写，模型逐帧重新解释脸 | 身份描述（脸/衣/身）留在静态 Identity Block；相机与运动另置 Motion Block |
| Wrong expression / frozen face（表情错/僵脸） | 缺微表情指导，或情绪线索冲突 | 用具体微表情术语；**一个镜头一种情绪** |
| Plastic / waxy skin（塑料/蜡像皮肤） | 角色工作选错模型，或描述过度平滑 | 换写实皮肤模型；加 "natural skin texture, subtle imperfections" |

**第 3 类 · Texture / Lighting Artifacts（质感与光照）—— 6 条**
起因：模型误读视觉风格或渲染指令（"misinterprets visual style or rendering instructions"）。

| 失败模式 | 成因 | 预防写法要点 |
|---|---|---|
| Flickering textures（纹理闪烁） | 各帧风格描述不一致，或模型在两个视觉风格间打架 | 只承诺**一个具名风格**；不混用竞争风格 |
| Over-lit / flat lighting（过曝/平光） | 提示词未指定光照，模型退回均匀通用光 | 永远写明光源与质感；**"No lighting specification" = 默认平光** |
| VFX preset looks cartoonish（特效预设卡通化） | preset 类型选错模型，或风格与特效冲突 | 写实类 preset → 写实模型；风格化 preset → 风格化模型；加 "photorealistic, physically accurate" |
| Product shots look cheap（产品显廉价） | 缺表面/背景规格，光照泛化 | 指明背景表面（"raw concrete"、"black velvet"）+ 质感线索 |
| Style ignored / generic output（风格被忽略/产出通用化） | 风格描述太含糊或根本没有命名 | 具名风格 + 具体调色："Style: Cinematic. Cold blue shadows, warm amber highlights, high contrast" |
| Color grade inconsistency（调色不一致） | 序列中各镜的颜色描述不同 | 在风格板锁调色，或**每个 prompt 重复完全相同的颜色语言** |

**第 4 类 · Whole-Frame Degradation — quality words vs. look choices（全帧降质：质量词 vs 风格选择）—— ★七类中法条含量最高，本节净增量核心**

**机制定义**：某些作者为了「film 感」去够的 token（`raw`、`masterpiece`、`8k`、`film grain`、`imperfect focus` 一类），被模型读作关于**渲染（rendering）**而非关于**主体（subject）**的指令——而一条渲染指令**落在整帧上**（"a rendering instruction lands on the entire frame"）：`film grain` 当质量注记丢进去，会软化画面里的一切；`imperfect focus` 会把整帧（含主体）带出焦。质量词不是只作用于你以为的那一处。

**管辖区分（governing distinction，判据）**：

> "*Content* may be imperfect — uneven light, an asymmetric composition, a messy room, an operator's wobble. *Image quality* must be sharp. **Imperfection is a subject choice; it is never a rendering instruction.**"
> （内容可以不完美——不均的光、不对称的构图、凌乱的房间、摄影师的手晃；**画质必须锐利。不完美是主体选择，永远不是渲染指令。**）

同一个词合法与否，取决于**位置与归属**：附着在具名主体/元素/时刻（或作品声明的 register）上合法；裸露吊尾、作为对画质的泛泛祈求，就是全帧降质。

**三种合法用法**（降质的是第四种：token 裸露丢入、不附着任何东西、吊在 prompt 尾巴上）：

| 合法用法 | 它是什么 |
|---|---|
| Look choice（风格选择） | 该 stock 或 texture 就是作品**声明的 register**，写在 Style / Look 槽里并说明它属于谁（一支 MV 开场即 "16mm grain"） |
| Optics as content（光学作为内容） | 一个**具名光学事件**、发生在**具名元素**上、在**具名时刻**（热浪游动、合焦前的短暂找焦） |
| Plate matching（贴片匹配） | 颗粒/模糊/焦外衰减与既有 plate 匹配，使合成元素不像贴上去的 |

**降质写法 → 替代写法（5 行）**：

| 写成裸质量注记 | 模型会怎么处理 | 改写为 |
|---|---|---|
| `film grain`（吊尾、不附着） | 噪点铺满整幅，精细细节随之软化 | 作为**有 stock、有归属**的 look 具名："Super 8MM warm grain, soft vignette"——或作为贴片匹配："grain matched to the reference frame" |
| `imperfect focus` / `soft focus` / `dreamy` | 全局锐度损失——主体连同一切一起变软 | 具名光学事件 + 元素 + 时刻："a brief focus hunt on the badge before it locks" |
| `edges not perfectly sharp` / `slight natural deviation` / `not completely stable` | 有效分辨率下降，画面读作糊 | 丢弃；把不完美放回**主体**：墙上歪的画框、崩口的杯子、只照到脸一侧的光 |
| `blurry background` | 主体跟着一起糊 | 说明**哪个平面保持锐利**——见 E4 |
| `hazy` / `foggy`（未量化） | 全帧雾，主体在内 | 只留给真正的空气透视，**量化且定位**（"haze ramps 20% → 70% behind the ridge"），并写明主体自身的锐度 |

**探针声明（要用本条必须带）**：本条证据形态为 EMPIRICAL——来自第三方提示词语料（本库未具名），原文自注 "not A/B'd on our own material"。建议探针：同一镜头两臂 480p 对照——A 臂结尾挂裸 `film grain, imperfect focus`，B 臂挂具名 look 替代，比较**主体细节保留度**。在该探针跑出来之前，本条是**起草偏好（a drafting preference），不是规则**——不拦截任何提示词，也没有任何 linter 强制执行。

**第 5 类 · Temporal / Consistency Artifacts（时间与一致性）—— 7 条**
起因：跨帧出现，或跨多次生成出现（"across frames in video or across multiple generations in a sequence"）。

| 失败模式 | 成因 | 预防写法要点 |
|---|---|---|
| Static I2V output（图生视频几乎不动） | prompt 重述了静态图，而不是该动的东西 | **只描述「变化/运动」的东西**；加显式相机运动与大气运动（"dust floats"、"steam rises"） |
| Camera movement not working（运镜不生效） | 相机被含糊描述，未用精确 preset 名 | 独行写精确 preset 名："Camera: Dolly In"，而非 "the camera slowly moves forward" |
| Contradictory camera movements（运镜互相矛盾） | 一个 prompt 里多个冲突相机 | 每镜**一个主运动**；需要多个则分开生成再串联 |
| Scene continuity breaking（场景连续性断裂） | 各镜角色/环境描述不同 | 逐字复制粘贴角色描述；用参考锚点锁一致性；锁风格板 |
| Motion preset not visible（运动预设不可见） | preset 未精确命名，或场景不支持该效果 | 按清单原名写；指令放在 prompt **末尾**；确保场景上下文支持该效果 |
| Lip-sync desync（唇同步失步） | 音频 > 8s、头部运动 token 与唇动引擎竞争、非 MP3 格式 | 对白 clip 裁到 3–8s；**移除所有头部/面部运动 token**；用 MP3；相机锁死或极慢 Dolly In |
| Background music overriding dialogue（BGM 压过人声） | 环境/音乐 token 诱使生成音频引擎替换上传音频 | 加时间戳锚定："Audio @Audio1 plays exactly as uploaded from 0s to end"；**移除全部 ambient/SFX/music token** |

**第 6 类 · Content Filter / Safety Artifacts（内容过滤与安全）—— 4 条**
起因：生成被拦截，或产出被净化的版本（"blocked or produce sanitized output"）。

| 失败模式 | 成因 | 预防写法要点 |
|---|---|---|
| Generation blocked（horror/dark content） | 平台安全过滤被露骨描述触发 | 写氛围不写行为："unsettling"、"something is wrong"、"dread"；用 motion preset 做恐怖效果 |
| Named real person blocked（真人姓名被拦） | 名人/公众人物姓名的内容过滤 | 用角色描述代替真名；创造原创角色 |
| Brand / IP name blocked（品牌/IP 名被拦） | 商标/版权过滤 | 按外观描述产品（"a matte black insulated mug, minimal design, no branding"），**绝不用品牌名** |
| Weapon / violence filtered（武器/暴力被过滤） | 露骨武器或伤害语言触发审核 | 写 "tension"、"aftermath"、"impact" 而非血腥伤害；用 motion preset 做 VFX |

**第 7 类 · Cinema Studio–Specific Artifacts —— ⚠️ 判为不收录**：全部绑定 Higgsfield 平台机制（512 字符硬限与 @ 标签吞隐形字符、3D Mode 几何空洞、光学栈须走 UI 下拉框），平台专属层不收录；其唯一可迁移切片（引擎不支持负向语法时全部改写为正向）已由 E3「平台无负向通道」口径覆盖，不单独立条。

**E2 · ★禁令何时仍然合法——一个测试，不是一张清单**

每次想写禁令之前，先问核心测试句：

> "**is the model's untouched default already the failure?**"
> （模型的**未触碰默认**，是否已经是失败？）

**判定程序（二分）**：
- **是** → 点名失败几乎零成本——禁令赢得位置，但必须**短、具体、后置**于正向事实之后（"written *after* the positive statement of what is true"）
- **否** → 禁令会**主动招呼**一个模型本不会渲染的东西——改写成正向形式（"the ban primes something the model was not going to render: write the positive form"）

**通过测试的禁例清单（7 条）**：

| 合法禁令 | 为什么通过测试 |
|---|---|
| 正向声明内部的**锁尾**（lock tail）："Consistent lighting, no flicker"、"Photorealistic — no 3D render" | 短、附着在所保护的状态上 |
| 打斗里的 **slow motion** | 模型自己就会去够它 |
| 必须静音的场景下的 **music bed** | 生成视频默认带一层垫乐（token 写法 `NO BGM` vs `No music.` 是开放问题，但禁令本身不是） |
| **Duplicates**（第二个模特、多出来的人） | 克隆是模型会去够的默认；以计数领起 |
| **复制**一个为旋律/节奏而挂的音频参考的**声音** | 未限定作用域的音频参考会外借它携带的每一项属性 |
| **调整错主体**（size-ref 靠编辑做出来的时候） | 模型会靠缩小它能缩的任何东西来解决比例问题 |
| 随**烘焙**属性一起跟来的垃圾（flares、streaks） | **只在素材阶段禁**，之后下游永不提及 |

**未通过测试的 4 类**：① 参考素材泄漏的颜色（"no yellow" → 改为**分配**它，见 I 论证一）；② 你不想要的图形风格（如地图风格——"never name the map's style, **not even negated**"）；③ 镜头已烘焙后的光学词汇；④ **任何独立存在的负面清单**（any freestanding negative list）。

**关键边界句（防过度泛化，必须与测试同时执行）**：一个词不因为它含否定就可疑——"no"、"never"、"without" **出现在正向声明内部**时，走同一个测试。本法条针对的是**负面清单与裸露否定**，不是每一个 "no" token。测试的作用对象是**禁令**（值不值得写），不是词；判定单位是**禁令所处的位置与形态**——独立负面清单 vs 正向声明内部的锁尾。

**与库内既有判定的关系（四条，必须连读）**：
1. **vs 删除测试（§二十七）**——删除测试问「删掉这半句，有没有任何一个唯一的可见/可听选择消失」，管**冗余**；本条问「禁令该不该写」，管**合法性**。两条同为判定式但轴不同，**并存不互替——否则会被当成同一条而丢一条**。
2. **vs 禁项前置（00 号 E18）**——E18 管**禁令放哪里**（模型反复忽略时，把禁止项移到素材绑定之后复测）；本条管**禁令该不该写**。须连用：**先过合法性测试，再按 E18 决定位置**。
3. **vs 反套路可见性测试（§二十七）**——同族（追问 → 强替换），但那边治**空泛词**（filler），本条治**负向词**。
4. **vs 污染七类扫描（§二十七）**——污染七类管**时间轴上的残留**（旧轮次污染）；E1 第 4 类的 Whole-Frame 机制管**空间轴上的作用域**（整帧降质）。不同轴，**并列不合并**。

**E3 · 负向提示强化与口径桥接（冲突处置写死）**

**规则**：当提示词在画面侧**声明了一条正向约束**（锁死的相机、一块黑区、一片刻意留空），就把**对应的排除项镜像写进负向侧**，让模型从两侧受约束（双侧夹）。

**配对例（3 组，原样可用）**：

| 正向声明 | 负向强化 |
|---|---|
| `Static locked-off camera. Zero movement.` | `camera movement, pan, zoom, dolly, shake` |
| `Left third: pure black, no motion, no light.` | `particles on the left side, light on the left side, movement on the left side` |
| `Foreground plane: particle layer only — no subject.` | `subject in foreground, character in foreground` |

**口径桥接（三条并存、不互替，写死）**：
1. 负向强化**只对结构性排除项开放**——相机运动 / 区域内容 / 区域占用；
2. **不对**「用户否掉的旧元素、旧上下文、旧模板残留」开放——那些一律**直接删除、不描述**（走 §二十七 污染七类之 2「纠错泄漏」）；
3. 目标平台**无负向通道**时，全部按 16 号口径**转正向锁**（「不要 X」→「保持 Y」）——无负向通道的平台上，负向清单等于没写。

**配套（留白区负向镜像，微增补丁）**：① 显式命名留白区并在负向侧镜像，阻止模型往空区填充无谓细节；② **联想式命名须以底层规则为前提**——先声明该区「无光、无动、无粒子」，再命名 `sacred emptiness` 才生效；无规则时联想命名 = 形容词堆叠。

**E4 · Depth of field —— 两个替代物、两个意图**

**前置法条**："No blur" 是**两个不同的请求**，正向替代物也不同；两种拼法**都正确、不可互换**。

| 作者真正想要的是 | 正向写法 | 何时用它 |
|---|---|---|
| 全帧由前到后都锐利 | "sharp focus throughout, deep depth of field" | 风景、建立镜头、群像 blocking、背景本身即信息的产品在场景镜头 |
| 主体锐利、背景**故意**柔 | "subject in sharp focus, background falling into soft bokeh" | 肖像、对白覆盖、在繁忙场景中孤立一个人物 |

**判定句**：第一个回答 "the whole image is mushy"（整幅画面糊）；第二个回答 "the background blur ate my subject"（背景虚化吃掉了主体）；`blurry background` 单独用**两个都不回答**——它 "never says which plane is meant to stay sharp"（从不说哪个平面该保持锐利）。（与 00 号 C7 分工：C7 管焦距/FOV 参数是否写全，本条管**意图**是否写清。）

### 边界（B）

- 失败模式表是**诊断索引**，不是每条都往提示词里塞——按用户反馈的坏法对号入座，只写适用的预防要点
- 禁令合法性测试治的是**禁令该不该写**；通过测试的禁令仍受 00 号 A6「正向与禁止不矛盾」一致性检查约束
- 负向强化三条口径按场景取用、不混用：结构性排除项才镜像负向；旧残留直接删；无负向通道转正向锁
- 探针未跑之前，Whole-Frame 机制按起草偏好执行，不作为拦截规则
- 与 §二十七 的关系：交付前两类**并列扫描**——那边扫时间轴残留，本节扫空间轴作用域与负向词合法性

## 三十二、接触约束拓扑（双物体约束关系 · action-choreography-reference 蒸馏）

**适用**：可信度取决于脚/手/武器/同伴/墙/檐/座/载具/生物/铰链/缆线/布层/落面时——即任何「两个东西连着」的关系（双人承接/抓握/骑乘/攀爬/拖拽/传接）。

**五段约束链**（把关系当临时物理系统）：
```
support/attachment（支撑/附着） → load transfer（载荷传递） → relative-motion limit（相对运动限）
→ reaction/lag（反应/滞后） → release or new constraint（释放或新约束）
```

**判句**：不要把相关身体或道具当独立图层动画，然后试图用模糊、粒子或运镜遮住分离。

（与二十六物理事件链互补：那边管**事件时序**——因→果不倒置、反应不早于触发；本节管**双物体约束关系**——载荷怎么传、相对运动被什么限制、何时释放。）

## 附：四维配音格式（说话镜头专用）

> 来源：`generate-four-dimensional-voice-prompt`（豆丁）蒸馏

带台词的说话镜头（数字人口播/短剧对白/图生视频说话），台词段强制四标签结构：

```
场景：[地点/时间/前置事件/人物关系/环境声；按情境写入景别机位灯光]
人物状态：[身体反应/心理/说话目的/表达阻碍]
发声方式：[音量/语速/气息/咬字/重音/停顿/音高/尾音]
台词："[带表演节奏标点的最终台词]"
```

发声方式是「情绪强度规则」（SKILL.md §五）在声音层的落地：克制态用鼻息短句，临界态语速加快咬字变硬，释放态音高下坠尾音拖长。与 09 §二十 台词节奏规范配合使用——09 管语速预算（字数/秒），本格式管发声质感。
