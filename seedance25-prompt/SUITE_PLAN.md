## 六、智能调度层设计（v0.2 新增 ★核心）

> 来源：AI STUDIO 洋子「ai-film-router」（2026-08-30 学习）+ 山音编剧「格式路由」+ 山音导演「输入兼容」。
> 王老师目标（2026-08-30）：**用户不需要知道要调用哪个子 skill，说出需求，套件自动分配到编剧/分镜/设定/拍摄/视频提示词对应阶段，并自动分段推进。**

### 6.1 调度器三层机制

```
用户一句话需求（"我要做一部60秒竖屏悬疑AI短片" / "帮我拆这场戏的分镜" / "这个角色图不对，重画"）
        ↓
【第一层】需求识别 → 判定工作模式 + 目标阶段
        ↓
【第二层】阶段路由 → 加载对应子 skill + 按格式缩放深度
        ↓
【第三层】进度管理 → 版本留档 + 阶段暂停等确认 + 下游过期标记
```

### 6.2 第一层：需求识别（学洋子「能判断时不要让用户填表」）

**四种工作模式**（自动从用户原话判断，模糊时只问一个问题）：

| 模式 | 触发信号 | 行为 |
|------|---------|------|
| **全流程** | "从零开始：我要做一部……" | 按阶段顺序推进，每阶段暂停等确认 |
| **指定阶段** | "帮我拆分镜" / "写这场戏台词" | 直接进入该阶段，不强迫补前序 |
| **接力** | 用户上传剧本/角色卡/资产图/分镜表 | 从已有材料能支撑的阶段切入 |
| **修订** | "回到剧本阶段，第 8 场动机不对" | 切回指定阶段修复，下游标记"可能过期" |

**模糊输入兜底**（学山音编剧）：一句话问清即可，不甩表单——"你想做哪种体量？1-3 分钟概念片 / 5-10 分钟短片 / 30 秒单元视频 / 多集？"

**「只做 X」直达模式交互规范**（学洋子手册第六章）：用户说"只做提示词/只做分镜"时——
1. 总控**只登记本轮指定的权威输入**（附件/图片/文档，只有用户明确"以这些为准"才成为权威输入）
2. 只调用目标子 skill，**不要求先跑完前序**，也不自动生成大纲/角色/分场等任何前序产物
3. 缺少非关键资料时只说明假设或询问**最小必要信息**，不补造整套上游

### 6.3 第二层：阶段路由表（学洋子「阶段×最小输入×标准输出」）

| 阶段 | 子 skill | 阶段作用 | 最小输入 | 标准输出 | 素材基础 |
|------|---------|---------|---------|---------|---------|
| 01 概念/编剧 | 01-screenwriting | 主题、类型、风格、受众、核心概念 → 剧本 | 一句话想法，或粗糙文本 | `01_story/synopsis.md` + 剧本 | workfish 钩子 + 山音编剧（格式路由：概念片/短片/长片/剧集） |
| 02 分镜 | 02-storyboard | 把故事拆成连续场次、事件、冲突、节奏 → 分镜表 | 剧本，或大纲+目标时长 | `05_shots/storyboard.md`（八/九列表） | workfish 分镜模板 + 山音导演九列表 |
| 03 设定资产 | 03-assets | 角色、场景、道具的描述符与图像提示词 | 剧本，或角色/场景/道具资料 | `03_assets/assets-vNN.md` | Gaven 图像导演 + Lira 防失败规则（03 文件 §6.8） |
| 04 拍摄表演 | 04-shooting | 目标、阻力、策略、节拍、潜台词、可见行为 | 当前场景/镜头 + 角色信息 | `04_performance/acting-vNN.md` | 山音导演五步 + 表演五大支柱（09 文件 §20.19） |
| 05 视频提示词 | 05-video-prompt（现 seedance25-prompt） | 根据当前镜头和现有资产生成可复制视频提示词 | 当前镜头 + 可用资产参考 | `06_prompts/cinedance-vNN.md` | 现有全部 references（含 17.6 FOV / 15.10 十二区块） |

> 对照洋子 8 阶段：其 1 概念锚定 / 2 角色圣经 / 3 世界观（可选）/ 4 分场大纲 / 5 剧本深度融合 → 咱们压缩为 01 编剧（世界观/角色圣经并入编剧阶段，符合"能内嵌不拆分"）；其 6 Lira / 7 ACTING / 8 CINEDANCE → 咱们 03/04/05 一一对应。

**格式缩放**（学山音）：同一工作流按体量缩放——概念超短片（30-90 秒）跳过世界观/长片结构，直接钩子→分镜→提示词；短片走全流程；长片/剧集先季度/幕规划再分段。**分段原则**：30 秒单元为基本生产单元（workfish 文戏法，见 04 文件 §9.4），长内容按单元接力推进。

**输入兼容**（学山音导演）：收到粗糙文本/大纲时，目标阶段前先做一轮快速梳理（整理成场景结构、标注核心事件），再进正式工作流——不强迫用户先跑完整前序。

### 6.4 第三层：进度管理与防污染（学洋子项目文件 + 山音步骤纪律）

- **项目文件夹**：`00_project/`（brief / project-status / routing）+ `01_story/ 02_script/ 03_assets/ 04_performance/ 05_shots/ 06_prompts/`——每阶段输出落盘，聊天窗口同步完整展示（学洋子：不要求用户开文件才能看到成果）
- **步骤纪律**（学山音）：每步完成暂停，等用户「通过 / 修改 / 自检」，绝不一次性生成所有内容
- **版本留档**（学洋子）：修改前旧版存 `00_project/history/`；修订后记录「影响范围 + 可能过期的下游 + 未受影响部分」，下游不删除不自动重写，由用户决定重算范围
  - 回退修订完整流程（学洋子手册第七章）：① 在**同一个项目任务**中直接说回退（分支气泡只适合比较 A/B 两种创意，正式版本必须留主任务；若用了分支，选定后把结果带回主任务并更新项目状态）→ ② 保存旧剧本、切回目标阶段、只修改指定问题 → ③ 把受影响的资产/表演/提示词标记为"可能过期" → ④ 确认新版后，**只重做受影响部分**
- **防串味 6 条**（学洋子手册第八章）：① 一次只调用一个专业 Skill；② 允许主动切换阶段，但不允许当前 Skill 偷偷改写其他阶段；③ 修订先留旧版本，只把真正受影响的下游标记为可能过期；④ 每部作品独立项目，空白模板无任何示例故事和资产；⑤ 每阶段结果既显示在聊天窗口也保存到项目文件；⑥ 聊天中修改后先更新新版文件，下一阶段只读最新已确认版
- **确认与切换口令**（学洋子）：`确认本阶段`（确认成果，全流程模式给建议下一步）/ `继续下一步`（仅全流程推进一格）/ `修改本阶段`（保留旧版生成新版）/ `切换到 XX` / `只做 XX`（立即改写路由）

### 6.5 中文口令卡（学洋子手册第十章「最短口令卡」）

| 场景 | 口令 |
|------|------|
| 从零全流程 | `从零开始：我要做一部……` |
| 接力（从剧本/资产开始） | `从剧本开始：以我上传的最终剧本和角色卡为准。` |
| 直达单阶段 | `只做提示词：使用我上传的资产图、角色卡和镜头说明。` |
| 回退修订 | `回到编剧阶段：修复第X场……，先不要重做下游。` |
| 确认推进 | `确认本阶段。` / `继续下一步。` |
| （未来）套件升级 | `升级当前项目到新版规则。` |

> 设计原则：用户不记命令词、说人话即可；口令卡只是"最快路径"参考。对应洋子的 `从零开始 / 从 Lira 开始 / 只做 CINEDANCE / 回到剧本阶段 / 确认本阶段` 五卡，替换为咱们的阶段名。

### 6.6 套件/项目升级机制（学洋子手册第三章）

未来套件版本迭代时（v1→v2），对旧项目：
1. **只备份并更新**项目根目录 `AGENTS.md` 与 `00_project/routing.md`，新增升级记录
2. **绝不修改**故事、角色、剧本、资产、表演、提示词、分镜表和历史版本
3. 旧项目在**新任务**中打开升级（不在旧聊天里继续测试）
4. 升级前向用户说明：会动什么、不会动什么，完成后报告备份位置和未修改范围
