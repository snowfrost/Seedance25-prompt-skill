### 2. 备用 OpenAPI 通道（ima-skill）：列表可用、正文不可用
按王老师全局记忆的既定回退规则（优先 ima MCP，不可用则转备用 API）切换到
`~/.config/ima/` 凭证，实测结果：

| 能力 | 接口 | 结果 |
|---|---|---|
| 列知识库 | `search_knowledge_base` | ✅ 可用 |
| 列库内条目 | `get_knowledge_list` | ✅ 可用（含 folder_id 进子目录） |

探测过的端点名（均无此路由）：
`get_media_content` / `fetch_media_content` / `get_knowledge_content` / `get_content` /
`read_content` / `get_media` / `media_content` / `get_media_text` / `openapi/wiki/v2/get_knowledge_list`

**关键发现**：`openapi/media/v1/fetch_media_content` 这个路由**存在**，但返回
`{"code":200000,"msg":"empty access token"}` —— 它要的是用户级 access token（OAuth），
不是 OpenAPI 的 clientid/apikey。试过把 apikey 放进
`ima-openapi-token` / `access-token` / `ima-access-token` / `x-access-token` 四种 header 及 body，
一律仍报 empty access token；改用 `Authorization: Bearer <apikey>` 则报
`{"code":110042,"msg":"token parse failed"}` —— 说明该 header 被读取，但 apikey 不是合法 access token。
→ **正文读取能力由 ima-mcp 连接器独占，OpenAPI 凭证拿不到。**
